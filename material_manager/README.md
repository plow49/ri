# M_물품관리
기존 ERP와 별개인 단일 사용자용 물품 반출·반입 기록 프로그램입니다.

1. ZIP을 쓰기 가능한 별도 폴더에 압축 해제합니다.
2. install-windows.cmd를 실행합니다. Python 3.12가 없으면 설치 후 다시 실행합니다.
3. 바탕화면 물품관리 또는 물품관리.cmd를 실행합니다.

항목 추가 버튼으로 물품명, 양의 정수 수량, 반출/반입, 교체/신규, 날짜, 이름을 입력합니다.
행을 선택하고 수정 버튼을 누르거나 더블클릭하면 모든 입력값을 수정할 수 있습니다.
반출/반입과 사유는 행별 편집 창의 선택 목록에서 선택합니다. 표 안에서 직접 입력하지 않습니다.
날짜 기본값은 PC의 오늘 날짜이며 YYYY-MM-DD 형식으로 변경할 수 있습니다.
취소하면 저장하지 않습니다. 자료는 프로그램 폴더의 materials.db에 저장됩니다.
ERP의 erp-local.db와 독립적이며, 별도 외부 패키지나 Oracle 연결이 필요 없습니다.
물품별 기준 총수량과 반출/반입 이력을 이용해 현재 수량을 계산합니다. 회계 기능은 없습니다.

백업: 프로그램을 닫은 뒤 materials.db를 복사하세요. 업데이트 때 해당 파일을 보존하세요.
Windows 실행은 아직 미검증입니다. 설치 스크립트가 PC에서 데이터 테스트와 GUI 생성 검사를 실행합니다.

## 1.1 물품별 총수량
상단의 물품 총수량 입력 / 수정 버튼으로 물품별 기준 총수량을 입력하세요.
기준 총수량은 모든 저장된 기록을 반영하기 전의 수량입니다. 현재 실사 수량을 그대로 입력하면 과거 기록이 이중 반영될 수 있습니다.
현재 수량 = 기준 총수량 + 누적 반입 - 누적 반출. 동일한 물품명은 합산합니다.
기준 총수량 미입력 품목은 미입력으로 표시합니다. 음수 현재 수량은 빨간색으로 표시하며 과거 기록 입력을 차단하지 않습니다.
기존 기록은 보존하며 별도의 inventory 테이블을 자동 추가합니다. 수정 저장 시 합계를 재계산합니다.
업데이트 전 프로그램을 닫고 materials.db를 백업하세요. 새 폴더에서 사용할 경우 기존 materials.db를 새 폴더에 복사한 후 실행하세요.

## 1.2 실행 이름과 아이콘
실행 파일을 물품관리.cmd로 변경했습니다. 설치 시 바탕화면과 프로그램 폴더에 M 아이콘의 물품관리 바로가기를 만듭니다.
CMD 자체 아이콘은 Windows 기본 아이콘입니다. 사용자 지정 아이콘으로 실행하려면 생성된 물품관리 바로가기를 사용하세요. 프로그램 창에도 M 아이콘을 적용했습니다.
기존 M_물품관리 바로가기는 자동 삭제하지 않습니다. 새 바로가기를 확인한 뒤 필요하면 직접 삭제하세요. 폴더를 이동한 경우 설치 스크립트를 다시 실행해 바로가기를 갱신하세요.

## 1.3 M 아이콘
프로그램 창과 물품관리 바로가기의 아이콘을 남색 배경·청록색 M 이미지로 변경했습니다. 설치 스크립트를 다시 실행하면 바로가기가 갱신됩니다.

## Windows EXE 빌드
GitHub Actions의 Build M Materials Windows EXE 작업이 물품관리.exe를 생성합니다.
완료된 실행의 Artifacts에서 M-Materials-Windows-EXE를 다운로드하세요(GitHub 로그인 필요).
EXE 자체에 M 아이콘을 포함하며 Python 설치가 필요 없습니다.
데이터는 EXE 옆 materials.db에 저장됩니다. 기존 데이터 사용 시 프로그램 종료 후 백업·복사하세요.
Windows 작업은 기존 테스트와 패키징된 EXE의 Tk/아이콘/SQLite 스모크 검사를 실행합니다.
실제 성공 여부는 해당 Actions 실행 결과로 확인해야 합니다. 코드 서명은 적용하지 않습니다.

## 자동 업데이트 (검토 중)
기존 설치본에는 업데이트 기능이 없으므로 이 기능을 포함한 EXE를 처음 한 번 수동 설치해야 합니다.
기능 포함 EXE는 시작 시 정식 GitHub Release를 확인하며 수동 업데이트 확인 버튼도 제공합니다.
사용자 승인 후 다운로드, GitHub asset SHA-256 비교, DB 백업, 프로그램 종료, 별도 도구의 EXE 교체와 재실행을 진행합니다.
DB는 현재 위치에 유지하고 materials.before-update.db에 업데이트 직전 백업합니다. 기존 EXE는 .previous.exe로 보관합니다.
파일 복사나 재실행 프로세스 시작 실패 시 이전 EXE를 복원합니다. 새 버전 실행 후 발생하는 업무 오류까지 자동 복구하는 것은 아닙니다.
Windows 실제 업데이트 검증은 아직 완료되지 않았습니다. 테스트 DB로 먼저 검증해야 합니다.

배포 계약: 공개 GitHub Release의 태그 materials-vX.Y.Z, 자산 이름 M-Materials.exe, GitHub가 제공한 sha256 digest가 필요합니다.
프로그램 updater.py의 VERSION을 배포 버전과 함께 갱신합니다. draft/prerelease는 업데이트로 표시하지 않습니다.
비공개 저장소나 네트워크 접근 실패 시 자동 업데이트는 불가능하며 기존 프로그램을 계속 사용할 수 있습니다. 토큰을 프로그램에 넣지 않습니다.
업로드할 EXE는 Windows 빌드 Artifacts의 물품관리.exe를 M-Materials.exe로 이름 변경하여 사용합니다.
정식 릴리스 게시에는 별도 사용자 승인이 필요합니다. 현재 정식 릴리스를 생성하거나 게시하지 않았습니다.

## 1.4.1 데이터 폴더 분리
Windows EXE 데이터와 업데이트 전 DB 백업은 %LOCALAPPDATA%\M_Materials에 저장합니다.
기존 EXE 옆 materials.db는 새 DB가 없을 때 SQLite 백업 API로 복사·무결성 검사 후 옮깁니다.
복구 사본 materials.migration-backup.db를 새 폴더에 보관합니다. 새 DB가 있으면 기존 파일은 건드리지 않습니다.
소스 실행은 개발용으로 기존 경로를 유지합니다.

## 1.4.3 실행 폴더 정리와 버전 표시
EXE와 CMD 모두 사용자 데이터 폴더를 사용합니다. 업데이트 백업 EXE도 해당 폴더의 backups에 저장합니다.
기존 실행 폴더의 materials.db는 이전하며, 새 DB가 이미 있으면 별도 legacy 복구 사본으로 보관합니다(자동 병합하지 않음).
기존 materials.before-update.db와 현재 EXE 이름의 .previous.exe도 검증 후 사용자 데이터 폴더로 옮깁니다.
하단에 버전 1.4.3을 표시합니다. 데이터 파일 자체는 기록 보존을 위해 사용자 데이터 폴더에 계속 존재합니다.

## 1.4.4 창 크기 대응 및 반출처
화면 구성은 유지하면서 작은 창에서는 전체 가로·세로 스크롤로 잘린 영역을 확인할 수 있습니다.
최소 창 크기 640×480, 내용 기준 폭 1120이며 큰 창에서는 가용 폭에 맞춰 확장합니다.
항목 추가·수정에 반출처(부서/장소) 입력칸과 기록 표의 반출처 열을 추가했습니다.
기존 DB에는 빈 반출처 열을 자동 추가하며 기존 기록·수량은 유지됩니다.

## 1.4.5 마우스 휠
전체 화면에 마우스 휠 세로 스크롤을 연결했습니다. 표에서는 목록을 우선 스크롤하고 끝에 도달하면 전체 화면을 스크롤합니다.
Shift+휠은 전체 화면 가로 이동입니다. 입력 대화상자는 별도이며 배경 화면 휠 처리에 연결하지 않습니다.
Windows EXE 자동 검증에 실제 MouseWheel 이벤트로 전체 화면과 기록 표 이동을 검사하는 절차를 추가했습니다.

## 1.4.6 업데이트 진행 표시
다운로드 진행률, 받은 용량, 경과 시간 및 예상 다운로드 남은 시간을 표시합니다.
전체 크기가 없는 응답은 진행 애니메이션과 받은 용량을 표시합니다. 남은 시간은 평균 속도 기반 추정입니다.
다운로드 100%는 설치 전체 완료를 의미하지 않으며 이후 검증·DB 백업·재시작 단계를 구분합니다.
이 화면은 1.4.6 설치 후 다음 업데이트부터 제공됩니다(기존 버전의 업데이트 UI는 변경 불가).

## 1.4.7 업데이트 종료·중복 실행 수정
OS 파일 잠금으로 동일 사용자 데이터의 프로그램 창을 하나로 제한합니다.
업데이트 도구는 기존 프로그램의 실행 잠금 해제 후 파일 교체를 진행하며, 교체 잠금을 해제한 뒤 한 번 재실행합니다.
PyInstaller 재실행 시 PYINSTALLER_RESET_ENVIRONMENT=1을 지정하여 이전 실행의 임시 환경을 공유하지 않습니다.
기존 버전으로부터 이번 업데이트까지는 기존 종료 동작이 사용됩니다. 새 버전에서 이후 업데이트부터 수정된 종료 절차가 적용됩니다.

## 1.4.8 상단 요약 및 UI 정리
등록 물품(종)과 전체 반출·반입 기록(건)을 상단 요약 카드로 표시합니다. 추가·수정·삭제 후 자동 갱신합니다.
남색 헤더, 흰색 카드, 청록색 추가 버튼, 옅은 빨간색 삭제 버튼, 교차 행 배경으로 화면을 정리했습니다.
하단에는 버전과 업데이트 버튼을 유지하고 작은 창 스크롤·휠 동작도 유지합니다.
Windows 빌드에서 빈 데이터/추가/삭제 시 상단 숫자 갱신과 휠을 검사하고, 예시 데이터의 화면을 UI-normal.png / UI-small.png로 제공합니다.

## 1.4.9 UI 표시 보정
Windows 화면 캡처에서 확인한 글꼴 우선순위를 수정하여 요약 카드 숫자와 섹션 제목의 크기가 적용되도록 했습니다.
내용 기준 폭을 920으로 줄여 일반적인 작은 모니터에서도 가로 잘림을 줄였습니다. 더 작은 창은 휠과 스크롤로 모든 기능을 이용합니다.

## 1.4.10 반출처 정렬
반출처 내용을 제목과 동일한 가운데 정렬로 바꾸어 이름 열 쪽에 붙어 보이던 현상을 수정했습니다. 저장된 값과 열 순서는 변경하지 않습니다.

## 1.4.11 표시 번호
반출·반입 기록의 번호는 위에서 아래로 1부터 연속 표시합니다. 최신 기록을 위에 표시하는 순서는 유지합니다.
추가·삭제 후 다시 매기며 실제 DB 식별자는 변경하지 않아 수정·삭제 대상은 그대로 유지합니다. 반출처 가운데 정렬도 포함합니다.

## 1.4.12 물품명 정렬
상단 수량 현황과 하단 이동 기록의 물품명을 모두 제목과 같은 가운데 정렬로 변경했습니다.
